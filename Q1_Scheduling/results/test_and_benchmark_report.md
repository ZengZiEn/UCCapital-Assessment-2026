# 題目一：排班問題 — 實測結果與跨語言效能測試報告 (`test_and_benchmark_report.md`)

## 1. 語言選擇策略與雙引擎實測摘要

在高頻交易（HFT）與量化系統研發中，我們採用 **「Python 高可維護性領域建模 + C11 暫存器級 Bitboard/SWAR 極速熱路徑」** 雙語言架構：
* **C11 原生引擎 (`src_native/fast_scheduler.c`, MSVC x64 `/O2`)**：參考西洋棋引擎（Stockfish Bitboards）與 SWAR（SIMD Within A Register）技術，將 4 位員工的工時上限計數打包進單一 32-bit 暫存器（每員工佔 4 bits），消除所有堆積記憶體配置與函式遞迴開銷。
* **Python 領域引擎 (`src/solvers.py`, Python 3.12)**：將遞迴熱路徑中的動態容器操作預編譯為平坦 Tuple 與定長整數陣列，兼顧高可讀性、完整型別檢查與微秒級回應。

| 評測項目 | Python 3.12 最佳化引擎 | C11 Bitboard / SWAR 原生引擎 (`MSVC /O2`) | 跨語言加速倍率 |
| :--- | :---: | :---: | :---: |
| **單解搜尋 (`solve_one`)** | `~11.90 us` (`11,900 ns`) | **`26.79 ns` (`0.0268 us`)** | **`444.2 倍`** |
| **全 34 解完整枚舉 (`solve_all`)** | `~59.80 us` (`59,800 ns`) | **`159.01 ns` (`0.1590 us`)** | **`376.1 倍`** |
| **突發請假最小變動修復 (`repair`)** | `~15.00 us` (`O(1)` 查表 `< 0.20 us`) | **`107.43 ns` (`0.1074 us`)** | **`139.6 倍`** |
