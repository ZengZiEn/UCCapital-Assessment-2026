## Obstacles

在 `TASK-04` 的跨題報告整合、無頭瀏覽器 PDF 渲染、GitHub 推送與工程治理重整過程中，主要遭遇以下四項報錯訊息與挑戰：

1. **障礙一：工作區路徑含空白與中文字元導致 Chrome/Edge 無頭模式無法渲染 PDF**
   * **報錯現象**：首次執行 `build_report.py` 呼叫 `chrome.exe --headless=new --print-to-pdf=... file:///C:/Users/user/Desktop/my datas/面試相關/...` 時，執行逾時或無法產出 PDF 檔案。
   * **原因分析**：工作區路徑中包含空白（`my datas`）與中文字元（`面試相關`），直接字串拼接 `file:///` 未經過 RFC 3986 URL 百分比編碼（Percent-Encoding），且沙箱環境下 Chromium 子行程需要 `--no-sandbox` 旗標。

2. **障礙二：SVG 圖表文字函式位置參數順序錯誤與 PDF 單行溢頁**
   * **報錯訊息 (Error Log)**：
     ```text
     SyntaxError: positional argument follows keyword argument
     ```
   * **原因分析**：在撰寫 `build_workflow_pdf.py` 時，誤寫 `svg_text(..., color=C_GREEN, "bold")`。此外，當報告新增「AI Agent 協同治理聲明」與「人機協作職責對照表」後，主報告第 14 頁的附錄程式碼區塊曾一度被擠到第 15 頁，流程報告第 3 頁的表格也曾被推到第 4 頁造成留白。

3. **障礙三：首次推送至 GitHub 新儲存庫 `ZengZiEn/UCCapital-Assessment-2026` 時遭遇 `403 Permission Denied`**
   * **報錯訊息 (Error Log)**：
     ```text
     remote: Permission to ZengZiEn/UCCapital-Assessment-2026.git denied to flysnow921103.
     fatal: unable to access 'https://github.com/ZengZiEn/UCCapital-Assessment-2026.git/': The requested URL returned error: 403
     ```
   * **原因分析**：本機 Windows 認證管理員（Credential Manager）先前快取的 GitHub 憑證為另一個帳號 `flysnow921103`，而非新建儲存庫之擁有者 `ZengZiEn`。

4. **障礙四：如何將「AI Agent 協同研發過程」與「The Chain of Truth 三層級管理規則」結構化融入專案而不顯雜亂**
   * **架構挑戰**：人類工程師（曾子恩）明確指示應誠實揭露使用 AI Agent 協同分析與實作的過程，並導入 `The Chain of Truth`（`/strategy/`、`/tasks/`、`/worklogs/`）三層級管理規範，同時保持專案根目錄與雙份 PDF 報告的清晰度與一致性。

## Resolution

針對上述四項障礙，我們採取了以下具體修復措施與架構整合，並已**向上同步更新**至 [`task.md`](file:///c:/Users/user/Desktop/my%20datas/面試相關/UCCapital/tasks/TASK-04-Visual-PDF-And-Governance/task.md)、[`implementation-process.md`](file:///c:/Users/user/Desktop/my%20datas/面試相關/UCCapital/tasks/TASK-04-Visual-PDF-And-Governance/implementation-process.md) 與頂層 [`/strategy/roadmap.md`](file:///c:/Users/user/Desktop/my%20datas/面試相關/UCCapital/strategy/roadmap.md)：

1. **使用 `pathlib.Path.as_uri()` 與 `--no-sandbox` 完美解決無頭瀏覽器 PDF 渲染**：
   * 於 `build_report.py` 與 `build_workflow_pdf.py` 中，改用 `pathlib.Path(html_path).as_uri()` 自動將空白與中文字元轉換為標準百分比編碼 URI，並加入 `--no-sandbox --disable-gpu --no-pdf-header-footer`，使兩份 PDF 能在 5 秒內穩定生成。

2. **修正語法並精確調校 SVG 與 CSS 版面高度，達成「主報告 14 頁整、流程報告 5 頁整」零溢頁**：
   * 將 `"bold"` 修正為具名參數 `weight="bold"`；並微調 `build_report.py` 第 14 頁的行距（`9.3pt / 1.42`）與 `build_workflow_pdf.py` 圖 3、圖 4 的高度（`218px` 與 `178px`），經逐頁檢視 PDF 渲染截圖確認：主報告恰好 **14 頁整**、流程報告恰好 **5 頁整**，版面緊湊勻稱、零溢頁。

3. **透過瀏覽器重新完成 `ZengZiEn` 帳號 OAuth 認證並隔離本機私密筆記**：
   * 協助人類工程師於終端機觸發瀏覽器 OAuth 認證切換為 `ZengZiEn` 帳號，順利完成 `git push -u origin main`；同時將本機複習用之 `INTERVIEW_QA_PREPARATION.md` 與 `.zip` 寫入 `.gitignore` 並執行 `git rm --cached`，確保 GitHub 公開儲存庫僅呈現純淨專業的交付內容。

4. **全面落地「The Chain of Truth」三層級管理框架與 Human-AI 協同透明揭露**：
   * 將開發規則正式寫入全域規則與專案根目錄 [`AGENTS.md`](file:///c:/Users/user/Desktop/my%20datas/面試相關/UCCapital/AGENTS.md)。
