## Obstacles

在 `TASK-03` 的影像逆向解析、統計證明與跨語言極速模擬過程中，主要遭遇以下四項報錯訊息與效能挑戰：

1. **障礙一：本機 Python 環境未安裝第三方影像處理套件 `PIL (Pillow)`**
   * **報錯訊息 (Error Log)**：
     ```text
     Traceback (most recent call last):
       File "<string>", line 2, in <module>
     ModuleNotFoundError: No module named 'PIL'
     ```
   * **原因分析**：本機為純淨之 Python 3.12 標準環境，未預裝 `Pillow` 或 `numpy`。

2. **障礙二：初版卡方檢定（Chi-Square Test）使用前一步統計出的常數，缺乏動態泛化性**
   * **程式碼審查問題**：在人類工程師要求「每一題實際跑過並檢查邏輯」時，發現初版 `src/hypothesis_prover.py` 的 `prove_directional_anisotropy_chi_square()` 內部直接寫死了 `a, b = 21, 15; c, d = 11, 29`。雖然針對本圖計算出的 $\chi^2 = 7.3895$ 數值無誤，但若更換輸入矩陣則無法動態重算。

3. **障礙三：C11 初版蒙地卡羅引擎使用 `% (i + 1)` 除法取餘數，導致 100 萬次洗牌耗時近 `300 ms`**
   * **效能瓶頸**：在 `src_native/fast_monte_carlo.c` 初版中，Fisher-Yates 洗牌使用 `xorshift64_star(&rng) % (uint64_t)(i + 1)`，實測 1,000,000 次耗時 `296.37 ms`。原因是 x86_64 CPU 的 64-bit 整數除法指令（`div` / `idiv`）延遲高達 25 ~ 40 個時脈週期，成為熱迴圈中的最大瓶頸。

4. **障礙四：批次檔 `echo` 訊息包含 `&` 符號觸發 Windows `cmd.exe` 語法報錯**
   * **報錯訊息 (Error Log)**：
     ```text
     'Python' 不是內部或外部命令、可執行的程式或批次檔。
     ```
   * **原因分析**：`Q3_PatternAnalysis/scripts/run_all.bat` 中原本寫有 `echo [3/3] Running Python Pattern Analyzer & Prover...`，未轉義的 `&` 被 `cmd.exe` 當成串接下一條指令的運算子。

## Resolution

針對上述四項障礙，我們採取了以下具體修復措施與演算法升級，並已**向上同步更新**至 [`task.md`](file:///c:/Users/user/Desktop/my%20datas/面試相關/UCCapital/tasks/TASK-03-Pattern-Analysis/task.md) 與 [`implementation-process.md`](file:///c:/Users/user/Desktop/my%20datas/面試相關/UCCapital/tasks/TASK-03-Pattern-Analysis/implementation-process.md)：

1. **手寫零外部依賴之 RFC 2083 標準純 Python PNG 底層解碼器 (`src/png_decoder.py`)**：
   * 直接使用標準庫 `struct` 解析 `IHDR` / `IDAT` 區塊、以 `zlib.decompress` 解壓縮像素流，並完整實作 PNG 五種掃描線濾波器（特別是 `Filter Type 4: Paeth` 預測器 $p = a + b - c$），在不安裝任何外部套件下 100% 精準還原 `575x313` RGBA 像素與 $9 \times 5$ Excel 標準四色矩陣。

2. **將方向異向性卡方檢定改為由 `self.grid` 動態遍歷統計**：
   * 修改 `src/hypothesis_prover.py`：移除常數賦值，改為直接遍歷 `self.grid` 的 36 條水平邊與 40 條垂直邊，動態累計同色系配對（冷色群 `{B,G}`、暖色群 `{R,Y}`）與跨色系配對次數，動態算出 `a=21, b=15, c=11, d=29` 與 $\chi^2 = 7.3895$（$p < 0.01$）。

3. **引進 Daniel Lemire 無除法範圍映射演算法（Fast Range without Division）加速 C11 蒙地卡羅引擎**：
   * 修改 `src_native/fast_monte_carlo.c`：將 Fisher-Yates 洗牌中的 `% (i + 1)` 替換為單週期 64-bit 乘法與右移位元運算：
     ```c
     uint32_t rnd32 = (uint32_t)(xorshift64_star(&rng) >> 32);
     uint32_t j = (uint32_t)(((uint64_t)rnd32 * (uint64_t)(i + 1U)) >> 32);
     ```
   * 重新以 `MSVC /O2` 編譯實測，1,000,000 次完整洗牌與 76 條邊正交衝突檢查總耗時由 `296.37 ms` 大幅降至 **`105.2 ~ 174.3 ms`（每 50,000 次僅需 `5.26 ~ 8.72 ms`，比未優化 Python 快逾 12 ~ 18 倍）**！
   * 此外亦針對考題完備性新增 `predict_next_rows()`（推演下一列 `Row 9` Top 1 為 `['R', 'G', 'B', 'G', 'B']`），6 項單元測試全數 `OK`。

4. **修復批次腳本特殊字元**：
   * 將 `Q3_PatternAnalysis/scripts/run_all.bat` 中 `echo` 內的 `&` 改為 `and`，消除 `cmd.exe` 解析警告。
