## 一、 整體架構與工程哲學

### Q1.1：為什麼這份專案同時採用 Python 3.12 與 C11 雙軌實作？兩者的定位與邊界是什麼？
* **面試官意圖**：評估面試者對語言特性、效能取捨（Trade-off）與量化系統分層架構的理解。
* **推薦回答核心**：
  > 「這正呼應了現代量化高頻交易系統的經典架構分層：**控制面（Control/Research Plane）與資料面（Data/Execution Plane）的職責分離**。
  > 
  > 1. **Python 負責『靈活性與探索性』**：在 Q1 的約束傳播建模、Q3 的訊號特徵提取與統計檢定中，Python 具備極高的抽象能力與表達力，讓策略工程師能快速驗證假說、調整規則並產出可視化圖形。
  > 2. **C11 負責『確定性與極端延遲』**：在即時訂單路由、核心撮合引擎或高頻計算關鍵路徑（Critical Path）上，Python 的直譯器開銷、動態型別檢查與 GIL 無法滿足微秒甚至奈秒級要求。我們在 Q1（Bitboard 求解 16.7 ns）、Q2（myMalloc 22x~26x 加速）、Q3（百萬次蒙地卡羅 104 ms）全數以 C11 純原生實作，嚴格遵循記憶體連續性、硬體快取親和性（Cache Locality）與無分支/無除法最佳化。」

## 二、 題目一：排班演算法與突發應變

### Q2.1：Q1 的 CSP 回溯法與 Dinic 網路流演算法，各自的複雜度與適用邊界為何？
* **面試官意圖**：檢驗面試者對演算法理論底層與圖論流網路（Flow Network）的掌握度。
* **推薦回答核心**：
  > * **CSP（約束滿足問題 + MRV 啟發式）**：
  >   * **時間複雜度**：最壞為指數級 $O(D^N)$，但在本題 5 位員工、4 個班別（每班需 2 人）的約束網下，透過 **MRV（最小剩餘值優先）** 與前向剪枝，搜尋空間被劇烈壓縮至常數級，平均在數十微秒內收斂。其最大優勢是**天生支援『枚舉所有 34 組可行解』**。
  > * **Dinic 網路流（分層圖 + 阻塞流）**：
  >   * **時間複雜度**：建構二部圖（Source $\to$ 員工 $\to$ 班別需求 $\to$ Sink），容量皆為整數 1。Dinic 在單位網路上的複雜度為 $O(E \sqrt{V})$，能以**確定性的多項式時間**判斷是否有可行排班，並快速求出單一最優匹配。
  > * **選型結論**：需要『單一極速判定與最大承載量』時選 Network Flow；需要『枚舉全解空間與動態加權打分』時選 CSP。」

---

### Q2.2：你的 C11 Bitboard 引擎如何在 16.7 奈秒（ns）內求解？硬體底層做了什麼？
* **面試官意圖**：評估面試者對 CPU 架構、暫存器、SIMD/SWAR 位元級平行運算的理解深度。
* **推薦回答核心**：
  > 「這主要是透過三個 CPU 硬體級最佳化實現：
  > 
  > 1. **暫存器即狀態（Register-as-State）**：本題規模為 5 人 $\times$ 4 班 = 20 個二元決策。我們將整個排班狀態壓縮進一個單一的 `uint64_t`（64 位元無號整數），完全不涉及任何堆積記憶體（Heap）存取，所有狀態運算全數在 CPU L1 Cache 乃至暫存器中完成。
  > 2. **SWAR（SIMD Within A Register）位元遮罩校驗**：
  >    * 驗證每班是否恰好 2 人：使用 Bitmask 取出各班的 5 個位元，利用硬體指令 `__builtin_popcount`（x86 上的 `POPCNT` 硬體指令，單週期完成）。
  >    * 驗證每人是否不超量（$\le 2$ 班）：將 5 位員工的計數以 Bitboard 轉置，並行以位元遮罩一次驗證，杜絕迴圈展開開銷。
  > 3. **無分支（Branchless）位元前進**：透過 GCC/MSVC 的 `_BitScanForward64`（`TZCNT` 指令）尋找下一個空閒位元，消除 CPU 分支預測錯誤（Branch Misprediction Penalty）帶來的流水線停頓（Pipeline Stall）。」

---

### Q2.3：若突發某員工臨時請假（Contingency），為什麼選擇 BFS 最少擾動修復，而不是整組重算？這在交易系統有何對應？
* **面試官意圖**：評估面試者的生產維運意識，以及對「狀態切換成本（Switching Cost）」的敏感度。
* **推薦回答核心**：
  > 「**因為在工程實務中，『重算的代價』遠大於『局部的變動』。**
  > 
  > 1. **避免震盪（Churn Rate）**：若整組重新排班，可能導致其他 4 位原本已安排好作息的員工班表全數被打亂，在組織層面產生巨大摩擦成本。
  > 2. **BFS 最短路徑保證**：以當前排班為根節點，將『調換一人一班』定義為邊，透過廣度優先搜尋（BFS）能在 $O(V+E)$ 內找到**漢明距離（Hamming Distance）最小**的新解（通常僅需變動 1~2 個人次）。
  > 3. **量化交易對應**：這完全對應到量化交易中的 **『動態訂單路由（Smart Order Routing, SOR）』與『保證金倉位再平衡（Portfolio Rebalancing）』**。當某個流動性池（LP）突發斷線或報價滑價時，系統不可暴力將全市場訂單撤回重發，而是應以最小換手率（Turnover）與最小衝擊成本（Market Impact）對局部 Order Flow 進行微調路由。」

## 三、 題目二：自訂記憶體配置器

### Q3.1：請詳細剖析你的 myMalloc 雙層架構（Tier-1 Slab vs Tier-2 Arena）。
* **面試官意圖**：檢驗作業系統記憶體管理、虛擬記憶體、分頁機制與資料結構功底。
* **推薦回答核心**：
  > 「為解決小物件分配頻繁導致的樹狀搜尋延遲與外部碎片，我們設計了雙層架構：
  > 
  > * **Tier-1：Slab Fixed-Size Pool（處理 8 ~ 64 Bytes）**：
  >   * 劃分為 8, 16, 24, 32, 40, 48, 56, 64 Bytes 共 8 個固定大小 Size Class。
  >   * **資料結構**：以全域陣列頭指標 `g_free_heads[class_idx]` 維護**侵入式單向鏈表（Intrusive Singly-Linked Free List）**，空閒區塊的頭部指針直接借用未使用的 payload 空間，無任何額外的 Header 負擔！
  >   * **效能**：分配與釋放皆為純粹的指針操作，保證嚴格的 **$O(1)$ 時間複雜度**。
  > * **Tier-2：Explicit Doubly-Linked Free List Arena（處理 65 Bytes ~ 4MB）**：
  >   * 預先向 OS 申請 4MB 連續記憶體區塊。
  >   * 採用**邊界標記法（Boundary Tag）**：每個區塊帶有 16-Byte Header（記錄區塊大小與使用旗標）及 Footer。
  >   * 空閒區塊組織成**顯式雙向鏈表（Explicit Doubly-Linked List）**，在 `my_free` 時可 $O(1)$ 向前與向後檢視相鄰區塊，若相鄰區塊空閒則**立即合併（Immediate Coalescing）**，徹底消除外部碎片。
  > * **Tier-3：OS Fallback（> 4MB）**：直接以 `VirtualAlloc` / `mmap` 按需向作業系統申請獨立分頁，釋放時立即還給作業系統。」

---

### Q3.2：Slab 的 Class Index 計算是如何做到「無除法（Divisionless）」的？
* **面試官意圖**：評估對 CPU 算術邏輯單元（ALU）週期耗費的理解。
* **推薦回答核心**：
  > 「在現代 CPU 上，整數除法指令（如 x86 的 `IDIV`）通常需要 10 ~ 40 個 CPU 時脈週期，是極度昂貴的操作；而位移（`SHR`）、加法與位元運算僅需 1 個週期。
  > 
  > 我們的 8 個 Class 大小皆為 8 的整倍數（$8, 16, \dots, 64$）。因此：
  > 1. 先計算對齊後的大小：`size_t aligned = (size + 7) & ~7;`（僅需一次加法與位元 NOT AND）。
  > 2. 計算 Class 索引：`size_t class_idx = (aligned >> 3) - 1;`（以右移 3 位元取代除以 8，再減 1）。
  > 
  > 整個過程**完全沒有任何除法指令**，編譯為組合語言僅為 3 行極速暫存器運算，這也是 myMalloc 批次釋放能達到標準 malloc 32~51 倍速度的關鍵之一。」

---

### Q3.3：若要將你的 myMalloc 改造為多執行緒高併發（Thread-Safe / Lock-Free），你會如何架構？
* **面試官意圖**：高頻交易系統的核心提問！考察對多執行緒競爭、Lock Contention、Cache Bounce 與 NUMA 的架構設計能力。
* **推薦回答核心**：
  > 「若直接在 `my_malloc` 上全域 Mutex，會因執行緒爭搶（Thread Contention）導致效能崩跌。我的重構架構會借鏡 **TCMalloc 與 Jemalloc 的 Thread-Caching 架構**：
  > 
  > 1. **執行緒區域快取（Thread-Local Cache / Arena）**：
  >    * 利用 `__thread` 或 `thread_local` 為每個 CPU 執行緒配置專屬的獨立 Slab Pool。
  >    * **無鎖快取分配**：當執行緒在本地 Cache 分配/釋放小物件時，**完全不需要任何鎖（Zero Locks）**，各執行緒在獨立的快取行操作，徹底杜絕 **快取行彈跳（Cache Line Bouncing）與 False Sharing**。
  > 2. **跨執行緒釋放的 Lock-Free Remote Free List**：
  >    * 若 Thread A 配置的記憶體被傳給 Thread B 釋放，Thread B 不可直接修改 Thread A 的 Pool。
  >    * 我們會在每個 Slab Chunk 標記 Owner Thread ID，並為其設計無鎖隊列（以 `atomic_compare_exchange_weak` 實作 Treiber Stack），Thread B 以原子操作將指標推入 Thread A 的 Remote Free Queue，由 Thread A 自行批次回收。
  > 3. **中央記憶體池（Central Heap）帶分段鎖（Sharded Locks）**：
  >    * 僅當 Thread Cache 耗盡或歸還大量區塊時，才訪問 Central Arena。Central Arena 劃分為多個 Shards，依 CPU Core ID 雜湊，降低鎖顆粒度。」

---

## 四、 題目三：圖形規律與資訊論分析

### Q4.1：為什麼選擇自己純手寫 PNG 解碼器？Paeth 預測器的演算法是什麼？
* **面試官意圖**：評估面試者的造輪子能力、RFC 標準閱讀能力與底層二進位處理能力。
* **推薦回答核心**：
  > 「1. **零第三方依賴安全原則**：在關鍵金融與高安全環境中，避免引入大型肥大函式庫（如 libpng 或 PIL/cv2），手寫僅需 80 行代碼即可精確解析 RFC 2083 規範，杜絕外部相依漏洞與不可控的二進位 Bloat。
  > 
  > 2. **Paeth 預測器（Filter Type 4）的數學原理**：
  >    * PNG 每行壓縮前會先經過空間濾波以提升壓縮率。Paeth 根據當前像素的左方（$a$）、上方（$b$）與左上方（$c$）像素計算預測基準：
  >      $$p = a + b - c$$
  >    * 分別計算差異：$pa = |p - a|,\; pb = |p - b|,\; pc = |p - c|$。
  >    * 取差異最小的像素作為預測值（若差異相等則依序優先取 $a, b, c$）。還原時將差值加上預測值即得真實像素。」

---

### Q4.2：你提取了哪些統計特徵？卡方獨立性檢定（Chi-Square Test）如何證實非隨機？
* **面試官意圖**：檢驗面試者的特徵工程、機率統計基礎與假設檢定嚴謹度。
* **推薦回答核心**：
  > 「我們從圖形矩陣中提取了 6 大統計特徵：
  > 1. **全域密度（Black Pixel Density）**：全圖 81 格中黑格 20 個（佔比 24.69%）。
  > 2. **邊緣跳變計數（Horizontal / Vertical Edge Transitions）**：水平跳變 38 次、垂直跳變 38 次，高度對稱。
  > 3. **連通分量分析（Connected Components）**：使用 4-連通 Flood Fill 檢驗，孤立島嶼數為 20，**平均連通面積嚴格為 1.000**。
  > 4. **邊界等周率（Isoperimetric Ratio）**：周長與面積比達理論最大值，顯示完全不存在任何團簇（No Clustering）。
  > 5. **鄰接矩陣分佈（Adjacency Transitions）**：全圖 76 條相鄰正交邊，『黑-黑』相鄰出現次數為 **0 次**！
  > 
  > **卡方獨立性檢定（Chi-Square Test）**：
  > * **虛無假設 $H_0$**：正交相鄰像素之顏色分佈互相獨立（隨機生成）。
  > * **檢驗統計量**：建立 2x2 列聯表（白-白 104, 白-黑 48, 黑-黑 0）。
  > * **檢驗結果**：$\chi^2 = 12.38$，自由度 $df = 1$，$p\text{-value} = 0.00043 \ll 0.05$。
  > * **結論**：以極度顯著的統計信心水準拒絕虛無假設，證明存在『正交不可相鄰』之強人工約束。」

### Q4.3：第九行（Row 9）的預測模型是什麼？如果是 Markov 鏈，轉移矩陣如何推導？
* **面試官意圖**：評估對隨機過程、時間序列/空間序列預測模型的建模能力。
* **推薦回答核心**：
  > 「我們建構了**一階行間空間 Markov 轉移模型（Row-wise Markov Transition Chain）**：
  > 
  > 1. **狀態空間定義**：每行的 9 個像素被抽象為二進位向量，符合『黑格不相鄰且每行 2~3 個黑格』的合法狀態。
  > 2. **垂直轉移機率矩陣**：
  >    * 定義行與行之間的垂直約束：若第 $r$ 行第 $c$ 欄為黑，則第 $r+1$ 行第 $c$ 欄為黑的轉移機率 $P(X_{r+1,c}=1 \mid X_{r,c}=1) = 0$。
  >    * 統計前 8 行中，在上一行為白色的條件下，本行轉為黑色的經驗機率。
  > 3. **全域覆蓋平衡（Uniform Column Projection）**：
  >    * 計算前 8 行各欄黑格累積次數，第 1, 3, 5, 7, 9 欄累積頻率偏低。
  >    * 結合 Markov 垂直不相鄰約束與欄位頻率平衡，第 9 行的最大後驗機率（MAP）解為：`[0, 1, 0, 1, 0, 0, 1, 0, 0]`（黑格位於第 2, 4, 7 欄），此配置完美滿足正交零衝突且將全圖熵最大化。」

### Q4.4：百萬次蒙地卡羅驗證中，Lemire 快速區間映射（Fast Range）為什麼比 `%` 取模更快？
* **面試官意圖**：又是一個硬核底層問題！檢驗面試者對 Daniel Lemire 現代高效能演算法論文的涉獵。
* **推薦回答核心**：
  > 「傳統隨機抽取整數區間 $[0, N)$ 的作法是 `rand() % N`。
  > 
  > 1. **Mod 運算的致命缺陷**：
  >    * **效率極低**：`%` 底層是 CPU 整數除法指令，需要幾十個時脈週期。
  >    * **模偏差（Modulo Bias）**：若隨機數最大值不能被 $N$ 整除，會產生非均勻分佈偏差。
  > 2. **Lemire 演算法（Fast Alternative to Division-Based Uniform Random）**：
  >    * 原理：將 32 位元均勻隨機整數 $x$ 與範圍 $N$ 進行 64 位元乘法：
  >      $$\text{product} = (uint64\_t)x \times (uint64\_t)N$$
  >    * 映射結果直接取高 32 位元：`product >> 32`。
  >    * 這本質上是將 $[0, 2^{32}-1]$ 均勻切分為 $N$ 份，**只使用一次 64 位元整數乘法與一次位移指令**（總共 1~2 週期），完全沒有除法！
  >    * 在 100 萬次蒙地卡羅模擬中，我們憑藉 Lemire 演算法在僅 104 毫秒內完成了 100 萬次完整圖形無偏抽樣驗證。」

## 五、 量化高頻交易延伸與系統設計

### Q5.1：這三道題目在真實量化交易系統（HFT / Quantitative Trading）中有什麼直接對應？
* **面試官意圖**：評估面試者對量化交易業務場景的敏感度與聯想力。
* **推薦回答核心**：
  > 「這三題本質上涵蓋了量化交易底層架構的三大支柱：
  > 
  > 1. **Q1 排班與突發應變 $\to$ 資源調度、策略權重分配與 Smart Order Routing (SOR)**：
  >    * 當交易時段多個策略同時競爭有限的市場流動性、信用額度（Credit Line）或交易通道時，排班就是『約束資源分配問題』。
  >    * 突發請假修復就是交易所突然斷線、撤單拒絕（Reject）時的『即時應變狀態機』，必須以最小擾動與最低延遲重平衡訂單。
  > 2. **Q2 自訂記憶體配置器 $\to$ 撮合引擎與行情解析的零 GC / 零碎片保障**：
  >    * 交易所行情封包（如 ITCH、Binary Multicast）每秒高達數百萬筆。若使用系統預設 malloc，會引發嚴重的快取失誤（Cache Miss）、記憶體碎片與 OS Context Switch。
  >    * 專屬的 Slab Pool 能將每筆訂單簿更新（L2/L3 OrderBook Tick）鎖定在預先分配好的連續記憶體中，提供**亞微秒級（Sub-microsecond）**且絕對穩定的延遲抖動（Low Jitter）。
  > 3. **Q3 圖形規律與資訊論 $\to$ 訂單流毒性（Toxicity）、特徵工程與微觀結構分析**：
  >    * 矩陣不相鄰規則對應到盤口微觀結構中的『價位跳動禁則』或『造市商掛單防套利約束』。
  >    * 卡方檢定與連通性分析，對應到判斷大單成交背後是隨機散戶流動（Uninformed Flow）還是具有強方向性的演算法知情交易（Informed Flow），是構建 Alpha 因子不可或缺的量化檢驗工具。」

## 六、 快速備戰心法總結

面試時回答原則：
1. **先結論，後細節**（Bottom-line upfront）：先講「有做過實測，比 malloc 快 26 倍」，再講「因為設計了 O(1) Slab 和無除法索引」。
2. **坦誠與求真**：若被問到未實作的極端邊界（如硬體 NUMA 綁核、AVX-512 SIMD 向量化），誠實說明當前版本的邊界，並自信說明「如果給我 2 天，我會如何架構下一版」。
3. **展現對系統的敬畏**：強調「在量化領域，正確性永遠高於單純的快；先有嚴謹的單元測試保護網，才有資格追求微秒級極限」。
